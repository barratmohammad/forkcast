# Project Proposal — ForkCast

**ForkCast is an AI recipe assistant that finds recipes by meaning (not just keywords), respects dietary needs, and builds meal plans grounded in a real recipe collection.**

## User Story

> As a home cook with dietary restrictions, I want to describe what I'm in the mood for and what's in my fridge, so that I get recipes and a weekly meal plan I can actually make — without scrolling through dozens of recipe sites.

## Required Components

| Requirement | How ForkCast meets it |
|---|---|
| FastAPI backend (3+ endpoints) | `/auth/register`, `/auth/token`, `/recipes` (CRUD), `/search`, `/ask`, `/meal-plans`, `/health` |
| SQLAlchemy (2+ related tables) | `users` 1→N `recipes`, `recipes` N↔N `tags` (via `recipe_tags`), `users` 1→N `meal_plans` N↔N `recipes` (via `meal_plan_items`) |
| Pydantic validation | Request/response schemas on every endpoint (e.g. `RecipeCreate`, `AskRequest`, `MealPlanRequest`) |
| JWT authentication | OAuth2 password flow, bcrypt-hashed passwords, Bearer token required on all non-auth endpoints |
| RAG pipeline | Recipes embedded into ChromaDB (`nomic-embed-text` via Ollama); top-k retrieval with dietary metadata filters; answers generated by Ollama (`llama3.2:3b`) with recipe citations. Guardrail: if no recipe is similar enough, the app says "I don't have a recipe for that" instead of letting the model invent one |
| Streamlit frontend | Login/register, recipe browser + editor, "Ask the Chef" chat, meal planner with a generated shopping list |
| Docker Compose | `docker compose up` starts backend + frontend; Ollama runs on the host |
| 5+ passing tests | pytest + TestClient: auth, CRUD, validation (422), RAG `/ask` with sources, health |
| README | Setup, architecture diagram, usage guide, endpoint table |
| requirements.txt | One per service (`backend/`, `frontend/`) |

## Data Source

790 recipes from **TheMealDB** (free public API, educational use), fetched once by a seed script and committed as `data/seed_recipes.json` so the app never depends on the API at runtime. Each recipe has a title, category, cuisine, ingredients with measures, and instructions. Dietary tags (vegetarian, vegan, gluten-free, dairy-free) are derived from ingredients. Users add their own recipes on top; those are embedded on save.

## Tech Stack

FastAPI · SQLAlchemy (SQLite) · Pydantic v2 · python-jose (JWT) · ChromaDB · Ollama (`llama3.2:3b`, `nomic-embed-text`) · Streamlit · Docker Compose · pytest

## Risks & Backup Plans

1. **Ollama is slow or gives weak answers.** Responses are capped with a timeout and a friendly error. Backup: switch `OLLAMA_MODEL` to `llama3.2:1b` for speed, or to a larger local model for quality. It's a single environment variable.
2. **Derived dietary tags are wrong** (e.g. a dish tagged vegetarian that uses fish sauce). Backup: keyword lists covered by unit tests, tags shown and editable on every recipe, and the LLM prompt tells users to double-check allergens. A recipe app that confidently mislabels allergens is the failure to avoid.
