# ForkCast Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build ForkCast — a recipe assistant with JWT auth, recipe CRUD, grounded RAG Q&A, meal plans and shopping lists — runnable with `docker compose up`.

**Architecture:** FastAPI backend (SQLite via SQLAlchemy 2.0, embedded ChromaDB) calls Ollama on the host over HTTP for embeddings and chat. A Streamlit frontend talks to the backend only via HTTP + JWT. Two containers, one named volume.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2.0, Pydantic v2 + pydantic-settings, python-jose, passlib[bcrypt] (or `bcrypt` directly), httpx, chromadb, Streamlit, pytest, ruff, Docker Compose.

**Spec:** `docs/design.md` (proposal: `docs/proposal.md`)

## Global Constraints

- Python 3.12 everywhere (`python:3.12-slim` images; local venv via `uv venv -p 3.12`).
- Diet tag names exactly: `vegetarian`, `vegan`, `gluten-free`, `dairy-free`. Chroma metadata keys: `vegetarian`, `vegan`, `gluten_free`, `dairy_free` (bool).
- Defaults: `OLLAMA_MODEL=llama3.2:3b`, `OLLAMA_EMBED_MODEL=nomic-embed-text`, `OLLAMA_TIMEOUT=90`, `RAG_TOP_K=5`, `RAG_MAX_DISTANCE=0.5` (tuned in Task 8), JWT expiry 60 min, HS256.
- nomic prefixes: documents `search_document: `, queries `search_query: `.
- Chroma collection `recipes`, `metadata={"hnsw:space": "cosine"}`, IDs `str(recipe.id)`. Score shown to users = `round(1 - distance, 3)`.
- No secrets in code; `JWT_SECRET` only from env. `.env` git-ignored.
- Every backend function has a docstring. `ruff check` and `ruff format --check` pass.
- Tests never call real Ollama (fake client via dependency override).
- User-facing error copy (exact):
  - Ollama down/timeout → 503 `"The AI model isn't responding. Is Ollama running?"`
  - Guardrail answer → `"I couldn't find a recipe in the collection that fits. Try rephrasing or loosening a diet filter."`
  - Bad login → 401 `"Incorrect username or password"`
  - Not owner → 403 `"You can only modify your own recipes"`
  - Allergy note (appended when tags used) → `"Diet tags are auto-detected from ingredients — always double-check labels if you have an allergy."`

## Review Focus

1. Ollama not running when the backend starts → backend still starts, `/health` 200 `degraded`, recipes browsable; `/ask` returns the 503 message. (Test in Task 6, startup tolerance in Task 8.)
2. LLM cites a recipe ID that wasn't retrieved (hallucinated `[#9999]`) → it never appears in `sources`. (Test in Task 6.)
3. Meal-plan LLM returns invalid JSON or unknown IDs → plan still created from top candidates, only real recipe IDs. (Test in Task 7.)
4. User edits ingredients of a recipe with no explicit tags → tags recomputed and Chroma metadata updated, so a vegetarian filter stops matching it once meat is added. (Test in Task 5.)
5. Expired/garbage JWT → 401, and the frontend sends the user back to login instead of crashing. (Backend test in Task 3; frontend handling in Task 9.)

### Task 6: `/ask` — grounded RAG with guardrails

**Files:**
- Create: `backend/routers/ask.py`, `backend/tests/test_rag.py`
- Modify: `backend/rag_pipeline.py`, `backend/schemas.py`, `backend/main.py`

**Interfaces:**
- Schemas: `AskRequest{question: 3–500 (strip whitespace), tags: list[DietTag] = []}`; `Source{recipe_id, title, score}`; `AskResponse{answer: str, sources: list[Source], grounded: bool}`.
- `rag_pipeline.answer_question(db: Session, index: RecipeIndex, llm, question: str, tags: list[str], top_k: int, max_distance: float) -> AskResponse`:
  1. hits = `index.search(question, tags, top_k)`; if none or `hits[0][1] > max_distance` → guardrail copy, `sources=[]`, `grounded=False`, **no chat call**.
  2. Keep hits with distance ≤ max_distance; load recipes from DB (skip IDs missing from SQL).
  3. System prompt: ForkCast chef; use ONLY the recipes provided; cite as `[#<id>]`; if none fit say so; never invent ingredients; concise. User message: numbered recipe blocks (`[#id] title — tags\nIngredients: …\nInstructions: …`) then the question and active diet filters.
  4. Parse cited IDs with regex `\[#(\d+)\]`; `sources` = retrieved recipes whose IDs are cited (in citation order); if none cited → all retrieved as sources and `grounded=False`; else `grounded=True`.
  5. If tags non-empty append the allergy note (blank line + copy).
- `POST /ask` 🔒 → `AskResponse`; `LLMUnavailable` → 503 copy.
